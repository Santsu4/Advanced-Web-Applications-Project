# Contributing Guidelines

This document defines the development practices for RIO.
All contributors should follow these guidelines to maintain a
consistent and organized codebase.

## Getting Started

1. Clone the repository.
2. Read the `README.md` to understand the project.
3. Read the [Architecture](docs/ARCHITECTURE.md) and
   [Coding Standards](docs/CODING-STANDARDS.md).
4. Follow the [Development Workflow](docs/DEVELOPMENT-WORKFLOW.md)
   for task selection, branches, commits, pull requests, and reviews.

Local environment setup instructions will be added once the
application is initialized.

## Contribution Checklist

1. Pick an available actionable issue, assign it to yourself, and set its sprint.
2. Update the task status and dates as you work, following the development workflow.
3. Create a branch using the agreed naming convention.
4. Implement the task according to the architecture and coding standards.
5. Run the available formatting, linting, and tests, and update relevant documentation.
6. Open a pull request linked to the issue, request review, and move the task to **In review**.
7. Address feedback and obtain the required approval before merging.
8. After merging, confirm the issue is closed and mark the task **Done**.

## Communication

- Use GitHub Projects to track tasks and progress.
- Use Discord for day-to-day work communication.
- Discuss significant architectural changes before implementation.
- Document important technical decisions.
- Communicate blockers and potential conflicts early.
- Review each other's work constructively.

## Updating These Guidelines

These guidelines may be updated as the project develops.
Significant changes should be discussed and reviewed by the team.
